# CLAUDE.md — StickyDesk

macOS 14+ post-it widget + menu bar app + MCP helper. Swift 6 language mode everywhere (strict concurrency), no third-party dependencies (XcodeGen is the only external tool).

## Commands

```bash
xcodegen generate --use-cache                       # regenerate StickyDesk.xcodeproj (only when project.yml or the file list changed)
cd Packages/StickyCore && swift test                # all unit + protocol + e2e tests
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcodebuild -project StickyDesk.xcodeproj -scheme StickyDeskApp -configuration Debug \
  -destination 'platform=macOS' -allowProvisioningUpdates build
```

`xcode-select` on this machine points at CommandLineTools, so `xcodebuild` needs `DEVELOPER_DIR`. `swift test` currently fails to build under CommandLineTools (MacOSX27.2 SDK, "error: fatalError"); run it with `DEVELOPER_DIR` set to Xcode too. Add `CODE_SIGNING_ALLOWED=NO` for a compile-only check.

## Architecture & decisions

- **All logic in StickyCore.** App/widget/MCP only call it. Store edits are pure `mutating` functions on `NotesStore` (`NotesStore+Editing`, `ReminderMerger`, `AgentOperations`) so they're testable and run inside the lock.
- **Persistence**: `NotesRepository` (actor). Writes = `update { inout store in … }`: acquire `flock` on sidecar `notes.lock` (polling with `Task.sleep`, 5 s timeout) → re-read file → mutate → skip if unchanged → atomic write (0600) → `didSave()`. The data file is replaced by rename, which is why the lock lives on a separate file. Reads are lock-free. A corrupt file is moved aside (`notes.corrupt-<ts>.json`) before being overwritten; `load()` returns an empty store on missing/corrupt files.
- **Migration**: every model uses `decodeIfPresent` with defaults. Added in schema v2: `Note.createdBy`, `idempotencyKey`, `createdAt`, `NotesStore.settings`, `agentCreationLog`. Later: `Note.completedAt` (`nil` = pending; MCP `list_notes` exposes `completed`). Keep new fields optional/defaulted.
- **App Group**: `STICKY_APP_GROUP` in project.yml → entitlements + `StickyAppGroupID` Info.plist key → `AppGroup.identifier`. Defaults to `<TeamID>.stickydesk` because a CLI can't embed a provisioning profile and macOS 15+ requires one for `group.`-prefixed IDs (verified: signed sandboxed helper accesses the container with no prompt). The helper gets an Info.plist via `CREATE_INFOPLIST_SECTION_IN_BINARY`.
- **Widget refresh**: app's repository `didSave` → `WidgetCenter.reloadAllTimelines()`. MCP `didSave` → Darwin notification `com.jfzepeda.stickydesk.store-changed` (+ best-effort reload). App observes it (`DarwinObservation`) and reloads. Timeline fallback: 30 min.
- **tilt** is random once at creation (−4…4), persisted, clamped on decode. Never derive from `hashValue`.
- **Widget**: reads via synchronous `StoreCodec.loadStore(from:)`; never touches EventKit. The only notes-store write is `ToggleNoteCompletedIntent` (check on each post-it's 22 pt band, right of the project name in black), which goes through `NotesRepository` + Darwin notification. Completed notes are hidden (`WidgetPresentation` uses `store.filtered(.pending)`), so checking one removes it. Post-its are 9:8 (`PostItMetrics`); the paper and its check are sibling controls, never nested. Slots: small 1, medium 2, large 4 (`SlotGrid`); unfilled slots are dashed outlines with a "+" `Link` (overview → `stickydesk://new-project`, inside a stack → `stickydesk://new-note?project=<id>`); when no slot is free the header shows "+ Proyecto"/"+ Nota"; zero notes → notebook sheet (`widgetURL` new note). Overview = one stack per project (`NotesStore.noteGroups`, unassigned/dangling notes share one stack); tapping a stack (`OpenStackIntent`) opens it in place with back + pager. Presentation logic is `WidgetPresentation` in StickyCore/Widget (tested). Browse state (open stack, pages) lives in `widget-state.json` next to `notes.json`, keyed per size (+ pinned project), written only by the widget's intents. `AppIntentConfiguration` with `StickyConfigurationIntent`: "Todos los proyectos" (default) or one project (`.pinned`, no back button; deleted project → all). Notes open the editor via `widgetURL` (small) / `Link`. Unverified: whether `Link` works in the small family on macOS (iOS ignores it there). 12 pt outer padding.
- **Version**: `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` live once in project-level `settings.base` of project.yml; app, widget and helper Info.plists use `$(MARKETING_VERSION)`. Don't change it in Xcode's General → Identity: that only edits the generated `.xcodeproj` and is lost on the next regenerate.
- Regenerating with XcodeGen replaces the open `.xcodeproj`, so Xcode shows "workspace file has disappeared"; use `--use-cache` and only regenerate when files are added/removed.
- **App**: `AppDelegate` owns `AppModel`, `PanelPresenter`, `RemindersImportController`. URLs arrive via `application(_:open:)` (MenuBarExtra doesn't reliably get `onOpenURL`) and are parsed by `DeepLink.action(from:)`: open note, new note (optional project), new project (`ProjectEditorForm` in a panel, since the MenuBarExtra window can't be opened programmatically). Projects are created/edited inline in the menu (swatch row from `Palette`, no `ColorPicker`: the color panel steals focus and the MenuBarExtra window closes). The note editor still opens in a floating `NSPanel`. Note text (menu quick-add and editor) uses `ListTextEditor` (`NSTextView` wrapper): `ListFormatting` in StickyCore turns "- "/"1 " into "• "/"1. ", continues lists on Return, ends them on an empty item; lists are stored as plain text. Return belongs to the text, so Añadir/Guardar are ⌘↩. Notes tab filters with `NoteFilter` (default `.pending`, also Todas/Completadas, not persisted) and has an inline-confirmed "borrar completadas" (`deleteCompletedNotes`).
- **EventKit**: `RemindersGateway` is `@unchecked Sendable` (wraps only `EKEventStore`); maps `EKReminder` → `ImportedReminder` inside the fetch callback. Empty list selection returns `[]` (EventKit's `nil` calendars means *all*). Selected lists and "clean orphans" live in app `UserDefaults`.
- **MCP**: hand-rolled JSON-RPC 2.0 (official swift-sdk was 0.12.x, pre-1.0, and the no-deps rule applies). Newline-delimited, 1 MiB message cap, no batches, stdout = protocol only, logs → stderr without user content. Tool errors are in-band `isError: true`; unknown tool → -32602. Limits/settings are enforced inside the lock against on-disk state, so they hold across multiple helper processes. Helper is sandboxed without network entitlement.
- `STICKYDESK_STORE_PATH` env override exists only under `#if DEBUG` (tests).

See README "Limitaciones conocidas". Unverified: whether `reloadAllTimelines()` from the CLI helper has any effect; app UI interactions were compiled and launched but not clicked through (no screen-recording permission in the dev session).

## Conventions

- No `try!`, `fatalError`, or force unwraps in normal paths.
- New mutations: add a pure function in StickyCore + a test, then call it from `AppModel.perform`.
- Sanitize all external text with `TextSanitizer` (Reminders titles, agent input).
- After big changes: regenerate, build, `swift test`, and update this file.
